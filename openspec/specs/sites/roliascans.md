# roliascans Site Plugin

- **Site name**: `roliascans` — **Domain**: `roliascan.com` — **File**: `sites/roliascans.go`
- **Cloudflare bypass needed**: no (plain HTTP requests to the site and to the `roliascan.org` image host answer 200 for any UA, verified with the api client's `kansho/1.0`).
- **Extraction**: `api` for both chapters and images, via the site's JSON API.

## What is scraped, how, and why

- **Chapter list**: the site runs a custom "mangapeak" WordPress theme (Tailwind markup). The manga page (`/manga/{slug}/`) server-renders only a loading spinner inside `<div class="chapter-list" data-manga-id="...">`; the real list is fetched over `GET /auth/manga-chapters?manga_id={id}&offset=N&limit=500&order=DESC&_t={token}&_ts={timestamp}` → `{success, chapters:[{id, chapter, title, chapter_type, group_id, language, group_name, likes, url}], total, offset, limit, has_more}`. Why: the chapters are not in the static HTML, and the API returns the full list (including absolute chapter URLs) in one request.
  - The request carries an anti-scraping token pair `_t`/`_ts` generated by the site's `manga.js`: `_ts` is the current Unix timestamp and `_t` is `md5(_ts + "mng_ch_" + UTC hour YYYYMMDDhh)` truncated to the first 16 hex characters. The plugin reproduces both.
  - The API supports pagination via `offset`/`has_more`; the plugin pages through with `limit=500` until `has_more` is false.
- **Chapter images**: `GET /auth/chapter-content?chapter_id={id}` → `{success, chapter_id, chapter_type, images:[...]}`. The chapter page itself only renders a spinner; the images list is API-only. The numeric `{id}` is taken from the chapter URL (`/read/{slug}/ch{n}-{id}/`).
- **Image hosts**: images are served from a separate domain, `roliascan.org/storage/chapters/...`, which answers plain HTTP with no challenge and needs no referer header, so the plain HTTP image downloader suffices.

## Chapter-list extraction flow

1. `GetChapterExtractionMethod`'s `APIFunc` fetches the manga page and reads the manga id from the `.chapter-list` `data-manga-id` attribute (falling back to `body[data-manga-id]`).
2. It generates the `_t`/`_ts` token pair and pages through `/auth/manga-chapters` until `has_more` is false.
3. Each chapter becomes `{num: chapter, id: chapterId, url: chapter url, text: title}`. Empty or `success=false` responses error out.

## Chapter download flow

1. `GetImageExtractionMethod`'s `APIFunc` extracts the numeric chapter id from the chapter URL and fetches `/auth/chapter-content?chapter_id={id}`.
2. The `images` array is trimmed, kept only for URLs starting with `http`, and de-duplicated.
3. Images are downloaded with the standard plain-HTTP downloader, converted to JPEG, and packaged into the CBZ.

## Normalization

- **URL**: unchanged — the API already returns fully-qualified `https://roliascan.com/read/...` URLs (relative paths would be prefixed with `https://roliascan.com`).
- **Filename** (`ch%03d[.frac].cbz`): pulls `(\d+)(?:\.(\d+))?` from the API `chapter` number (e.g. `91` → `ch091.cbz`, `1.5` → `ch001.5.cbz`). Unparseable labels fall back to a slugified `label.cbz` with a warning.

## Retry & backoff

Default policy (no `GetRetryPolicy` override):

| Operation | Total attempts | Backoff |
|-----------|----------------|---------|
| Chapter-list / image-list fetch | 3 | `2^attempt × 1s` |
| Chapter download | 3 | `2^attempt × 1s` |
| Image download | 3 | `2^attempt × 1s` (adaptive deadline: 2min base, +10s/fail, 30min cap) |
